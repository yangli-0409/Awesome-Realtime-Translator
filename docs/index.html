一、PRD 技术假设的核实结果

核实方式不是查网页，而是直接读 SDK 26.5 里的 .swiftinterface——带 @available 标注，比文档权威。

PRD 的假设实测处理
macOS 15 + Translation 框架即可 错TranslationSession(installedSource:target:) 标注 @available(macOS 26.0, *)。macOS 15 上唯一拿到会话的途径是 SwiftUI .translationTask，非 UI 层拿不到 部署目标定 macOS 26.0
7.4 #2：识别任务会在停顿后结束，需要无缝续接且不丢音频 已消失这是 SFSpeechRecognizer 的模型。SpeechAnalyzer 是常驻 actor，输入是永不结束的 AsyncSequence，没有「会话时长」概念 不写重启逻辑，F3 该条验收标准作废
F11：术语表作为「识别器的提示词」 换入口官方入口是 AnalysisContext.contextualStrings，模型在解码阶段加权，比拼 prompt 可靠 数据通路已接好，缺编辑 UI
7.4 #3：SCStream 输出格式与识别器不一致，需要 AVAudioConverter 确认需要。SpeechAnalyzer.bestAvailableAudioFormat 给目标格式 转换放在采集队列上，不占识别线程
7.4 #5：屏幕录制权限授予后需重启进程 确认TCC 判定在进程启动时缓存 引导页写明，并提供「立即重启」按钮
ScreenCaptureKit 能排除本进程音频 确认excludesCurrentProcessAudio（macOS 13+） 同时把本应用窗口从内容过滤器排除，双保险

二、架构

SystemAudioCapture ──PCM──► SpeechAnalyzerTranscriber (ScreenCaptureKit) │ TranscriptEvent (.volatile / .finalized) ▼ Segmenter ← 纯逻辑，22 个单测 │ Sentence（定稿后不可变） ▼ 翻译串行队列（Translator 协议） │ ▼ CaptionStore (@Observable) ──► CaptionPanel (NSPanel)

两条反闪烁规则（PRD 7.4 #1）

  • 原文区 = 已定稿句子 + 当前未定稿尾句。只有最后一行会变。
  • 译文只对已定稿句子生成，走串行队列保证顺序，一旦出现不再改写。

断句的三条定稿规则

  • 句末标点——但排除缩写（Dr.）、小数（1.5）、人名缩写（J. Smith）、句中省略号（Well... it depends）
  • 静音超过 450ms
  • 单句超过 140 字符时在词边界硬切（防止面试官一口气说三分钟导致整段不出译文）

三、PRD §10 未决问题的决定

问题决定理由
最低系统版本macOS 26换来直接可用的 TranslationSession 和 SpeechAnalyzer，砍掉两类难点和一半代码。代价是放弃 macOS 15 用户
屏幕共享时隐藏字幕窗做了，默认开NSWindow.sharingType = .none。不检测共享状态——窗口对所有录屏 API 从源头不可见，自己照常看得见
会话记录默认行为默认不保存面试记录含对方可识别信息，默认留痕不友好。想复盘自己开；当前这场随时能复制/导出
首发语言对英→中已接通，法/德/日/西在 UI 里未实测加语言只是改 identifier
产品名称 / 定价 / 免费限时没做，代码里零计时零内购定价要先做竞品调研，PRD 自己也列为待办

四、已验证 / 未验证

已验证
  • Swift 6 SWIFT_STRICT_CONCURRENCY=complete 下零错误编译
  • 22 个 Segmenter 单测全过。其中 3 个真实 bug 是测试逮出来的：no. 被误判成缩写、省略号后切不开、切句残留前导空格
  • Release 打包成 .app，启动后进程存活、无崩溃报告、菜单栏图标正常
未验证——需要在你本机跑一次
  • 系统音频实际有没有抓到声音。ScreenCaptureKit 需要 TCC 授权，必须你点同意，这是最大的未验证风险点
  • 识别准确率、端到端延迟（目标 <1s，译文 <1.5s）
  • 翻译语言包未安装时的下载流程
  • 60 分钟连续运行的稳定性与 CPU 占用（目标 <30% 单核）
  • 插拔耳机 / 切换输出设备后的自动恢复（有 didStopWithError 重启 + 12 秒无音频看门狗，逻辑未实测）
  • 中文作为源语言的识别效果
  • 「语音识别无需单独授权」这个结论；若实测仍弹 Siri 授权框，改 Permissions.speechRecognitionState 读 legacySpeechState 即可

五、最小验证步骤

不用开 Zoom。say 是独立进程，会被系统音频采集到：

say -v Samantha "Tell me about your experience with distributed systems. How many nodes did you run in production?"

预期：原文边说边出字，句末标点处定稿，下面出现中文译文，译文出现后不再改写。

六、隐私是技术约束，不是承诺

  • .entitlements 里没有 com.apple.security.network.client——沙盒从系统层面阻断任何出网请求
  • 音频只在内存里流过识别器，不写文件，没有录音代码路径
  • 字幕窗不会出现在任何录屏或共享画面里
