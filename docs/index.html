实时

本机

一次网络请求都没有

识别和翻译都用 macOS 自带的本机模型。沙盒里没有申请网络权限，这是技术上的保证，不是口头承诺。

隐蔽

不抢焦点、不进 Dock

字幕窗不接受键盘焦点，你在 Zoom 里打字不会被打断。没有 Dock 图标，可选鼠标穿透。

不留痕

不录音、不落盘

音频只在内存里过一遍就丢掉，任何时候都不写文件。文字记录默认也不保存，想留要自己打开。

可调

出字节奏你说了算

滑块在 0.3~1.0 秒之间调：跟手一点会看到字一跳一跳，顺滑一点就要多等半秒。

克制

不生成回答

没有「建议答案」功能，以后也不会有。面试是你在面，它只负责让你听清对方说了什么。

延迟是多少，有实测

不说「极速」「毫秒级」这种话。下面是埋点量出来的真实数字。

环节实测说明
系统音频采集21ms 一块不是瓶颈
语音识别吐字每 ~950ms 一批模型的解码窗口，改不了
字幕显现节奏0.5s（可调）把一批字摊开匀速放，避免一跳一跳
端到端约 1.5 秒对方说完一句到你看到译文

安装

大约两分钟。授权之后需要重启一次应用，这是 macOS 的行为，不是故障。

  1. 下载解压，拖进「应用程序」

    解压得到 AwesomeRealtimeTranslator.app。

  2. 首次打开：绕过「无法验证开发者」

    这个应用是 ad-hoc 签名的，没有苹果开发者证书，所以 Gatekeeper 会拦。在 Finder 里右键点图标 → 打开，或者在终端运行一次：

    xattr -dr com.apple.quarantine /Applications/AwesomeRealtimeTranslator.app
  3. 给「屏幕与系统音频录制」权限

    macOS 把「采集系统声音」归在这一项权限下。应用只读音频，不截图也不录屏。首次启动会自己弹授权框。

  4. 点「立即重启应用」

    macOS 在进程启动时缓存权限判定结果，刚授权的进程读到的还是旧值。引导页上有重启按钮。

  5. 完成

    字幕窗出现在屏幕顶部中间，点左上角 ▶ 开始听。

已知限制

这些是现在就知道的，写在这里省得你踩。

  • 只支持 macOS 26 及以上。用的是 macOS 26 才有的本机识别和翻译 API，更低版本装不上。
  • 延迟约 1.5 秒。其中约 1 秒是识别模型的解码窗口，软件改不了。
  • 只采集系统播放的声音，不采麦克风。也就是说它听得到面试官，听不到你自己。这是刻意的。
  • 没有苹果开发者证书。每次更新都要重新授权一次屏幕录制，因为 macOS 按代码签名哈希记授权。
  • 实测只验证过英语 → 中文。其它语言对框架上支持，但没测过。
  • 合规提示：不同国家和地区对会议录音 / 转写的告知义务不同。本应用不录音、不保存音频，但文字转写是否需要告知对方，请你自行确认。

常见问题

为什么要「屏幕录制」权限？会不会被截屏？

macOS 把「采集系统正在播放的声音」归在「屏幕与系统音频录制」这一项权限下，没有单独的「系统音频」权限可申请。应用只取音频流，画面帧直接丢弃。

对方真的看不到吗？

字幕窗设了 sharingType = .none，对所有录屏和屏幕共享 API 都不可见，包括你自己的采集。不过请先用会议软件的共享预览自测一次——有些软件直接抓屏幕原始画面，不遵守这个标记。

它会把我的面试内容传到云端吗？

不会。识别和翻译都用 macOS 自带的本机模型，应用的沙盒 entitlements 里根本没有申请网络权限——不是「我们承诺不联网」，是技术上发不出请求。

为什么译文是一整句出现，而原文是逐词出现的？

刻意的。边说边翻的话，中文语序和英文不一样，译文会被反复重写，整行乱跳，比多等一秒难受得多。所以只有整句定稿后才翻译，译文一旦出现就不再改。

能帮我生成回答吗？

不能，以后也不会做。产品边界是「只帮你听懂，不替你回答」。

会不会很耗电？

识别和翻译都跑在 Apple 芯片的神经引擎上，比云端方案省电。但长会话的 CPU 占用还没有实测数据，别把它当已验证结论。
